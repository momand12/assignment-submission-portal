# Problems Faced

Every problem we hit while building the project, what caused it, and how we fixed it.

| # | Problem | Cause | Fix |
|---|---------|-------|-----|
| 1 | GitHub CLI was logged in as another student's account (`iabdullahjan`). | The laptop is shared, and gh had two accounts with the other one active. | Ran `gh auth switch -u momand12` and checked with `gh api user`. |
| 2 | `winget install ngrok.ngrok` said "No package found". | The winget package ID is `Ngrok.Ngrok`, not `ngrok.ngrok`. | Ran `winget search ngrok` to find the right ID, then `winget install Ngrok.Ngrok`. |
| 3 | After `ngrok update`, Windows Defender blocked the new ngrok version (3.39.13) as `Trojan:Win32/Kepavll!rfn`. | Antivirus programs often flag tunnel tools like ngrok, because attackers also use them. | We did not turn off or bypass the antivirus. The old version (3.3.1) installed by winget was still there and working. |
| 4 | My first "defect" for the demo (making the last line of `is_valid_url` return True) did not fail the required `test_invalid_url_is_rejected_and_not_saved` test. | The scheme check (`http`/`https`) ran before that line, so `not-a-valid-url` was still rejected. | Moved the demo defect into `validate()` (`if False:` instead of the URL check), which really accepts every URL. Tested it locally: the required test fails. |
| 5 | Could not check the JavaScript validation from the command line. | Node.js is not installed on this laptop. | Served `site/` with `python -m http.server` and tested `isValidUrl()` and the form in a browser. Results matched the Python version exactly. |
| 6 | `setup-ngrok-token.bat` seemed to work, but no token was saved and the tunnel stayed offline (`ERR_NGROK_3200`). Running ngrok gave "Permission denied". | Windows Defender kept blocking the updated `ngrok.exe` in `WinGet\Links` (`Trojan:Win32/Kepavll!rfn`) every time it ran, so `ngrok config add-authtoken` never ran. | Checked Defender's detection history to find the cause. Changed both `.bat` files to use the original ngrok 3.3.1 copy in `WinGet\Packages`, which Defender does not block and which ngrok's servers still accept. |
| 7 | With the token saved, ngrok 3.3.1 still would not start: `Your ngrok-agent version "3.3.1" is too old. The minimum supported agent version for your account is "3.28.0"`. | ngrok's servers no longer accept old agents, and every new version (3.28+) is blocked by Windows Defender on this laptop. | ngrok cannot work on this laptop without weakening the antivirus, so we stopped and considered the fallback the exam allows: running the CI runner locally (self-hosted runner). |
| 8 | We wanted to keep ngrok, but neither `ngrok.exe` version could be used (problems 6 and 7). | `ngrok.exe` is the part Defender blocks. | Used ngrok's **official Python package** (`pip install ngrok`, version 1.7.0), which has a modern ngrok agent built in. `receiver/tunnel.py` opens the same static domain with the same account and token. Defender did not flag it. Tested end to end: the public URL reached the receiver, a good token saved the report and a wrong token was rejected. |
